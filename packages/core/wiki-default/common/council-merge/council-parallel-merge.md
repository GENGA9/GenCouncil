병렬 위원은 각자 브랜치에서 "통과"를 보고하지만, 합친 결과는 아무도 확인하지 않은 상태다.
일괄 변환 충돌, 다른 위원의 산출물 유무에 기대는 테스트, 밸런스 변경 두 개의 합이 대표적인 함정이다.

## 언제 쓰나
- 같은 저장소에 위원 여럿을 동시에 배정할 때, 둘째 이후 머지 직후

## 방법
### 일괄 변환(색·이름·포맷)이 낀 병렬 작업
- 금지 파일 목록만으로는 충돌을 못 막는다(같은 파일 다른 줄).
- 일괄 변환 지시의 완료 조건 끝에 "마지막에 git merge agenda/<안건> 후 충돌 해결·재검증"을 넣는다.
- 이미 충돌했으면 council_handover(다른 provider 가능) reason에: "git merge <통합 브랜치> → 상대 레이아웃·삭제 의도 유지, 이 브랜치 변환 규칙(스크립트 경로)을 상대가 새로 넣은 선언에도 적용 → tsc·test·build·캡처 → 머지 커밋"(30~40 calls).
- 핸드오버 한도("already handed over 2 times")면 `council_verify(member_id, model, reason)`로 같은 브랜치에 해결 위원을 붙이고, 머지는 원래 소유 위원 id로 한다.

### 그림 위원과 코드 위원을 동시에 돌릴 때
- 코드 위원이 "그림 없으면 대체 아이콘"을 테스트로 단정하면 그림 머지 뒤 테스트가 깨진다(기능은 정상).
- 대체 경로 검사는 "그림 경로를 먼저 찾는다 + 없을 때 대체가 있다"처럼 그림 유무와 무관하게 쓴다.
- 코드 위원 지시: "아이콘 PNG는 다른 위원이 만드는 중. PNG 존재·부재를 단정하는 테스트 금지".
- 이미 깨졌으면 haiku low로 테스트만 고친다.

### 밸런스에 영향 주는 변경 둘
- 둘째 머지 직후 "측정만" 위원(싼 모델, 소스 수정 금지, RESULT.md에 기준별 표)으로 같은 기준·판 수로 재측정한다. 각자 잰 결과를 합쳐도 특정 층·무기에 0% 구멍이 날 수 있다.
- 깨진 곳은 강한 모델에 원인 진단(피해 몫 등 숫자)+최소 수정을 맡긴다.
- 병렬 배정 때 체크포인트 다음 할 일에 '통합본 재측정'을 적어 둔다. 0%가 나오면 판 수를 늘려 재확인.

## 주의할 점
- 같은 파일을 만지는 후속 작업은 동시에 배정하지 말고 add_task로 앞 머지 뒤에([실행 중인 위원 지시 바꾸기](common/council/council-change-running-instruction)).
