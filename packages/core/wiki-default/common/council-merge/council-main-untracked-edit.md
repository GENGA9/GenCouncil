메인 폴더(main checkout) 안의 git 밖 산출물은 worktree·머지 보호를 받지 않는다. 사용자의 다른 도구가 같은 폴더를 쓰면 백업 전에 원본이 덮일 수 있고, 미추적 복사본은 안건이 같은 경로를 추적할 때 머지를 막는다.
배정 전에 동시 작업을 멈추고 전체 백업을 먼저 하며, 메인 커밋·merge_base는 마지막에 한다.

## 언제 쓰나
- 메인 폴더 안의 미추적 산출물(생성물·자료 폴더)을 위원이 고치거나 git에 넣어야 할 때
- 메인의 미추적 파일 때문에 머지·council_merge_base가 막힐 때

## 방법
- 배정 전: 대상 폴더의 최근 수정 시각을 확인하고, 사용자에게 같은 폴더를 쓰는 다른 도구를 멈춰 달라고 한다. 전체 백업을 먼저 한다.
- 지시에 대상 경로와 백업 경로를 절대 경로로 적고, `git status`로 메인이 어떤 브랜치인지 확인하게 한다(메인이 main이 아닌 브랜치일 수 있다).
- 안건이 같은 경로를 추적하게 되면 메인의 미추적 복사본은 바이트·이력 대조 → 백업 → 삭제 순으로 정리한다. `git merge-tree --write-tree`로 충돌을 미리 본다.
- 작업 중간에 메인에서 그 경로를 추적시키지 않는다. 위원 수정이 메인을 더럽혀 merge_base가 막힌다.
- 메인 커밋·merge_base는 메인을 쓰는 위원이 모두 끝난 뒤에 한다.

## 주의할 점
- 대용량을 git에서 빼면 git 원격 백업에서도 빠진다는 점을 사용자에게 알린다.
- 결과물을 저장소 밖 새 폴더에 만드는 일은 [결과물이 저장소 밖 새 폴더일 때 위원 분장](common/council/council-external-output-folder).
