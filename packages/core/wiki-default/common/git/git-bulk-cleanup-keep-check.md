큰 작업을 끝내고 옛 초안 mp4·스템·조각·후보 영상 수백 개를 지울 때, 최종 재현 스크립트나 외부 패키지 manifest가 옛 파일(_old 구간 영상, 후보 클립, 그래프 json)을 몰래 읽고 있을 수 있다. 최종 편집 프로젝트가 간접적으로 쓰는 파일(마스터 소리를 다시 만드는 입력, 원 생성물)도 빠뜨리기 쉽다.
눈으로 고르면 빠뜨리므로 보호 목록 → 이름 grep → 고정점 → 거꾸로 검사 순서로 기계적으로 고른다. 조건 분기·간접 경로 때문에 정적 grep으로 알기 어려운 입력은 파이프라인을 드라이런해 실제로 열리는 파일을 기록한다.

## 언제 쓰나
- 작업을 끝내고 중간 산출물을 수백~수천 개 단위로 정리할 때(git 추적 파일이든 git 밖 공유 폴더든)
- 수십 번 고친 영상 작업 폴더(수천 개 파일, 십수 GB)에서 "최종본과 조립용 파일만 남기고 지우기"를 할 때
- 지운 뒤 최종 스크립트가 여전히 돌아가는지 증명해야 할 때
- "이 스크립트를 다시 돌릴 때 실제로 열리는 파일"을 정확히 알아야 할 때

## 방법
### 0. 두 작업으로 나눠 배정
- '목록 작성(삭제 없음)'과 '삭제 실행'을 다른 작업으로 배정하고 그 사이에 사용자 승인을 받는다.
- 범위: git 추적 파일·다른 작업 폴더는 처음부터 범위에서 뺀다. 작은 문서·메타는 용량 이득이 없으므로 남긴다.

### 1. 보호 목록 먼저
- 남겨야 하는 패키지(예: 외부 패키지 manifest와 그 하위 json)의 모든 문자열 값 중 파일 경로로 풀리는 것을 모아 후보에서 처음부터 뺀다.
- 최종 편집 프로젝트(.kdenlive/MLT XML)의 모든 producer/chain `resource`를 파싱해 보존한다.

### 2. 후보 = 경로 패턴 규칙 + 이유 열
- 옛 판 폴더·`*-draft-*.mp4`·`_old/`·`sample-*` 등 규칙으로 후보를 뽑고 규칙(이유)을 함께 적는다.

### 3. 이름 grep (정방향)
- 모든 추적 텍스트 파일(.py .sh .json .mjs .md .kdenlive …, 후보 자신 제외)에서 후보 이름을 찾는다. 다른 문서·스크립트가 참조하는 후보는 플래그를 단다.
- 토큰: **저장소에서 이름이 유일하면 파일 이름만**, 겹치면 `부모/이름`. `부모/이름`만 쓰면 `$P/<이름>.json` 같은 변수 경로 참조를 놓친다(실제로 놓쳤다).
- 파이썬 정규식 하나에 후보 수백 개를 `|`로 묶어 파일마다 `findall` 하면 7천 파일에 2분 안쪽.

### 4. 고정점
- 남는 코드·설정이 참조하는 후보는 보류로 돌리고, 보류된 코드가 다시 참조하는 후보도 보류(바뀌지 않을 때까지 반복).
- 참조가 '그 스크립트의 출력 경로·옛 분석 도구 기본값·주석'뿐인 것만 근거를 적고 지운다.

### 5. 실제로 읽는 입력 추적: audit hook 드라이런 (파이썬 파이프라인)
- 최종 재현 스크립트(예: 마스터 소리 생성)를 드라이런하며 `sys.addaudithook(hook)`으로 `open`(읽기/쓰기 모드 구분)·`os.link`·`shutil.copyfile`·`subprocess.Popen`을 기록한다. 실제로 열린 입력 파일을 보존 목록에 넣는다.
- soundfile(libsndfile)은 C에서 파일을 열어 `open` audit 이벤트에 안 잡힌다 → `soundfile.SoundFile._open`(0.14, `mode_int` 0x10 = 읽기)을 감싸 경로를 기록한다.
- 쓰기는 `.council/`(임시 폴더) 아래만 허용하고 그 밖이면 `PermissionError`로 막아 공유 폴더 오염을 막는다.
- 드라이런 출력을 기존 산출물(마스터)과 `np.array_equal`로 비트 비교한다. 비트 동일이면 추적이 완전하다는 증거가 된다.
- 순서:
  1. `tempfile.tempdir`을 `.council` 아래로 바꾼 **뒤에** 훅을 켠다(안 하면 tempfile이 temp 폴더 쓰기 검사에서 막혀 시작을 못 한다. bg.mjs는 TEMP 환경변수를 넘기지 않아 env로는 안 된다).
  2. 출력 폴더 상수를 모듈 속성으로 `.council`로 바꿔 놓고 단계 함수를 호출한다.
  3. `nul`은 `//./nul`로 정규화돼 막힌 것처럼 보이므로 무시한다.

### 6. 승인 뒤 삭제
- 삭제 직전 verify(보존 목록·참조 검사)를 다시 돌린다.
- 삭제 목록(경로·크기·해시)을 로그로 남긴 뒤 지운다.

### 7. 삭제 뒤 거꾸로 검사
- 남은 코드에 적힌 경로 문자열(`[\w./-]+\.(mp4|wav|json|…)`) 중 지운 파일로 풀리는 것을 뽑아 하나씩 확인한다(같은 이름의 남은 파일을 가리키는 오탐을 걸러낸다).
- 그리고: 패키지 검사기(check_manifest 등), 최종 실행 스크립트 정적 검사(`bash -n`, 읽는 경로 존재, 로컬 import 사슬), 편집 프로젝트(.kdenlive resource) bin 검사·짧은 렌더, 납품물 해시, 마스터 재현, 다른 작업 단위 `git diff --name-only <해시>`가 0인지.
- git 밖 캐시(work-*, ComfyUI cache/)는 원래 저장소에 없으니 정적 검사에서 뺀다.

### 8. 삭제 목록 md (git rm일 때)
- 경로·크기·이유·남김 근거 확인 열로 표를 쓰고, **삭제 전 HEAD 해시**와 되살리기 명령 `git checkout <해시> -- <경로>`를 적는다.

## 주의할 점
- 이 커밋을 메인에 merge하면 메인 체크아웃의 그 파일들도 디스크에서 지워진다(의도한 정리라면 맞다, [git 추적 해제·제외 함정](common/git/git-untrack-exclude-pitfalls)).
- 지운 파일을 가리키던 위키·문서 예시는 되살리기 해시(`git show <해시>:<경로>`)로 바꿔 둔다.
- 위원 작업 폴더(`_shared/<안건>/<위원>/`)를 통째로 삭제 후보로 보지 않는다. 원 생성물의 유일 본이 거기 있을 수 있다.
