단위(에피소드·챕터)마다 안건 브랜치를 따로 돌리는데 생성기가 전 단위 합본 파일을 통째로 다시 쓰면, 자기 단위만 고쳐도 병합할 때마다 충돌한다. 일회성 스크립트가 합본 정본을 통째로 덮어쓰는 것도 원인이다.
해결은 정본을 단위 폴더로 나누고, 합본은 git에서 빼서 `build-all` 한 명령으로 같은 경로에 다시 만드는 것이다.

## 언제 쓰나
- 단위별 병렬 브랜치가 매번 같은 합본 md·html 뷰어·json·로그에서 충돌할 때
- 공용 생성기 안에 단위별 규칙이 하드코딩돼 한 단위 규칙이 다른 단위로 샐 때

## 방법
### 1. 조사·설계만 먼저 맡긴다
- 코드 변경 없는 설계 작업으로 시작한다. 결과물: 정본/생성물 구분표, 읽는 곳·쓰는 곳 지도, 공용 코드 안의 단위별 하드코딩 목록.
- 열린 브랜치들이 대상 파일을 얼마나 바꿨는지: `git diff --stat main...<브랜치> -- <경로>`.

### 2. 파일을 셋으로 나눈다
- 정본: 단위 폴더(`units/U01/…`)에 두고 git으로 추적한다.
- 단위별 생성물: 그 단위가 바뀔 때만 바뀌므로 추적해도 된다.
- 전 단위 합본·보기용: .gitignore에 넣고 `git rm --cached`로 뺀다. `build-all` 한 명령으로 같은 경로에 다시 만든다. 사용자가 여는 경로는 바뀌지 않는다.

### 3. 단위 하나를 더해도 다른 단위 파일이 안 바뀌게
- 흔한 함정: 단위별 파일 머리에 전 단위 목록(앵커·색인)을 넣는 것.
- 검사: 가짜 새 단위 모듈을 임시로 넣고 생성기를 전부 돌린 뒤 `git status`가 비었는지 본다.
- 위원에게 완료 조건을 줄 때 목적("다른 단위가 바뀌어도 이 파일은 불변")도 함께 적는다. "머리 ≡ 기준" 같은 조건만 주면 문자 그대로 지키다 이 함정을 남긴다.

### 4. 공용 도구는 하위 호환으로
- 단위 폴더가 있으면 단위별로 읽고 쓰고, 없으면 옛 경로를 쓴다.
- 옛 합본 정본과 단위 폴더가 함께 있으면 멈추게 한다(옛 일회성 스크립트가 옛 경로에 파일을 되살리는 사고 방지).
- 같은 방식으로 옛 경로를 직접 읽는 곳이 더 있는지 grep해서 함께 고친다(지시한 파일만 고치면 이웃 파일을 놓친다).
- 합본이 없을 때 조용히 0건으로 정상 종료하는 도구가 없는지 본다(예: 투표 루프가 컷 0개로 끝남).

### 5. 옛 결과와 같은지 대조
- 같은 worktree에서 `git restore --source=<기준커밋> <코드들>`로 옛 체인을 잠시 되돌려 기준판을 만든다([옛 커밋 기준판](common/git/git-restore-old-baseline)). 커밋본과 원래 다른 '기준 예외'(파일 존재 여부로 바뀌는 값 등)를 먼저 확인한다.
- HEAD로 복구한 뒤 합본을 지운 깨끗한 상태(`git clean -X`)에서 build-all을 돌리고 비교한다.
- 비교는 줄 끝 CR을 무시하고, JSON은 파싱해서 깊은 비교를 한다. 생성 시각 줄과 미추적 파일 유무로 바뀌는 줄은 '예상 차이'로 따로 분류한다.

### 6. 덧붙이기 로그는 동결
- 옛 실행 로그 파일은 추적한 채 더 쓰지 않고, 새 로그는 git 밖 `logs/`에 둔다.
- `git rm --cached`로 빼면 병합하는 순간 사용자 폴더에서 파일이 지워진다([git 추적 해제 함정](common/git/git-untrack-exclude-pitfalls)).

### 작업 분할 순서
- 설계 → (데이터 분리·생성기)와 (공용 도구) 병렬 → (build-all·gitignore) → (전체 대조·README). 서로 파일이 겹치지 않는다.

## 주의할 점
- main에 반영하면 main 폴더의 합본이 지워진다. 반영 직후 main 폴더에서 build-all을 한 번 돌리라고 사용자에게 알린다.
- README에 남길 것: 진행 중 브랜치가 따라오는 절차(합본 modify/delete 충돌은 삭제 쪽을 고름, 옛 정본은 split 스크립트로 자기 단위 키만 옮김 → build-all)와 새 단위 추가 절차.
- 단계 사이에 넘겨줄 도구·스크립트는 앞 위원이 커밋하게 한다. 미커밋 `.council/` 파일은 머지 뒤 worktree와 함께 사라진다.
- 한 줄 JSON·이미 어긋난 생성물의 일회성 병합은 [한 줄 JSON·생성물 파일의 병합 충돌](common/git/git-merge-special-files).
