새로 공개된 무료 API로 채팅 페이지를 먼저 만들고 실제 호출은 나중에 했더니, 응답 헤더에서 하루 100회 한도가 드러났다. 사용자는 기능 전체를 버렸다.
공식 문서 본문에는 한도 숫자가 없고 별도 Rate Limits 페이지에만 있었다.

## 언제 쓰나
- "공개된 ○○ API로 페이지 만들어 줘" 같은 요청을 받았을 때

## 방법
- 조사 단계에 한도 확인을 필수로 넣는다. 구현을 배정하기 전에 확인할 것: 일·분·초 한도, 동시 요청 수, 무료 기간.
- 문서의 Rate Limits·Pricing 페이지를 WebFetch로 읽는다.
- 키가 있으면 구현보다 먼저 1회 호출해 `x-*-rate-limit*` 응답 헤더를 본다.
- 한도가 작으면(예: 일 100회, 여러 사용자가 키 하나 공유) 숫자를 사용자에게 먼저 보여 주고 진행 여부를 council_ask_user로 묻는다.

## 주의할 점
- 한도 숫자는 문서 본문이 아니라 별도 페이지에만 있을 수 있다.
- 실키 검증은 [위원이 .env·비밀 파일을 다룰 때](common/council-members/member-secrets-env) 규칙을 지킨다.
