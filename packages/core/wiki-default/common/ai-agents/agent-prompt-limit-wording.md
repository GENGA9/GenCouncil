시스템 프롬프트에 권고("주간 사용량 30% 미만이면 최상위 모델은 쓰지 않고 상위 모델도 꼭 필요할 때만")와 실제 코드 차단이 한 문장에 섞여 있으면, 에이전트가 그 provider 전체를 "제한 걸림"으로 받아들여 제한 없는 하위 모델까지 피한다. 사용자는 "사용량 남았는데 왜 안 쓰냐"고 묻게 된다.

## 언제 쓰나
- 에이전트용 프롬프트에 사용량·비용·모델 선택 규칙을 넣을 때
- 코드가 어떤 요청을 거절하고, 그 거절 오류 메시지를 쓸 때

## 방법
- 규칙마다 세 가지를 각각 한 문장으로 적는다:
  - 막힘(코드): 코드가 실제로 거절하는 조건
  - 권고: 지키면 좋은 것
  - 예외 경로: 거절 조건을 넘는 정당한 방법(예: 사용자가 명시하면 override 옵션)
- 제한 없는 대상을 이름으로 적는다. 예: "sonnet·haiku는 사용량 제한이 없다: 남은 사용량이 적어도 평소처럼 쓴다".
- 기준값(예: 30%)은 프롬프트에 하드코딩하지 않고 설정값을 동적으로 출력한다. 코드와 프롬프트가 어긋나지 않게 한다.
- 거절 오류 메시지에 다음 행동을 넣는다: 더 낮은 모델을 쓰거나, 사용자가 명시했으면 override.

## 주의할 점
- 예외 경로는 프롬프트와 오류 메시지 양쪽에 안내한다. 한쪽에만 있으면 에이전트가 막힌 뒤 할 일을 모른다.
