Gen Wiki 페이지를 고치거나 주제 폴더로 옮길 때(감수·전체 점검) 도구 동작을 몰라 출처(sources)를 잃거나 깨진 링크를 남기기 쉽다. 아래는 위키 도구가 실제로 어떻게 움직이는지와, 옮기기 전 정해 둘 순서다.

## 언제 쓰나
- 위키 페이지를 고치거나(wiki_write) 다른 경로·하위 폴더로 옮기거나 나눌 때
- 페이지를 지우거나 합칠 때(wiki_remove)
- 한 페이지의 출처 목록·역링크를 확인할 때

## 도구 동작
- `wiki_write`를 같은 경로에 `sources` 없이 부르면 기존 sources가 그대로 유지된다. 같은 경로에 `sources`를 주면 기존 목록을 바꾸지 않고 거기에 더해진다(다른 페이지에서 절을 옮겨 올 때 그 절의 출처만 넣으면 된다). 새 경로로 옮기거나 나눌 때는 sources를 직접 넣는다.
- 한 페이지의 sources 목록은 `wiki_read`에 안 나온다(개수만). `wiki_search`에 그 페이지 제목 낱말을 넣고 `limit: 1`로 부르면 결과에 sources 배열이 나온다. 한 폴더의 페이지를 여럿 옮길 때는 `wiki_search`에 그 폴더 경로(`<폴더>`)를 넣고 `limit: 30`으로 한 번 부르면 그 폴더 페이지들의 sources가 한꺼번에 나온다(결과가 매우 길다).
- `wiki_remove`는 그 페이지를 링크하던 페이지를 알려 주지 않는다("removed <path>"만).
- `wiki_search`에 옛 경로 문자열(예: `<옛 폴더>/video-jobs`)을 넣어도 `-`·`/`로 토큰이 쪼개져 새 경로(`video/jobs`) 페이지들이 위에 뜬다. 역링크 찾기에 못 쓴다. 결과마다 sources 전체가 붙어 limit 10만 돼도 매우 길다.
- `wiki_read`는 3000자 넘는 페이지를 목차만 준다. 링크 확인은 `section: "주의할 점"`으로 싸게 볼 수 있지만 본문 중간 링크는 못 본다(`full: true` 필요).
- `wiki_toc <폴더>`는 폴더 안 페이지의 제목·요약을 한 번에 준다(index 페이지 한 줄 안내를 쓸 때 쓴다).
- 긴 페이지를 하위 페이지로 나누거나 주제 폴더(index 추가)로 옮기면 머리말·index 때문에 전체 글자 수는 오히려 늘어난다(본문 글자 수만 센다. 제목·요약을 줄여도 안 준다). 전체 글자 수를 줄이려면 겹치는 서술을 링크로 바꾸는 압축을 함께 한다.

## 페이지를 옮기거나 나눌 때 순서
1. 옛 경로 → 새 경로 표를 먼저 정한다.
2. 새 경로에 쓸 때는 옮기는 내용의 sources를 직접 넣는다(옛 페이지 sources는 위 wiki_search로 확인).
3. 다시 쓰는 페이지마다 그 표로 링크를 고친다. 같은 폴더에 남는 페이지 가운데 옮긴 페이지를 링크하던 것도 함께 다시 쓴다.
4. 옮긴 뒤 남은 역링크는 링크가 있을 법한 페이지를 직접 읽어(`full: true`) 고치고, 못 본 페이지는 보고서에 옛→새 경로 표와 함께 남긴다.
5. 페이지를 나눴으면 그 폴더 index에 새 페이지 한 줄을 더하고, 옛 페이지 머리말에 옮긴 절이 어디로 갔는지 링크를 남긴다(다른 페이지의 "…의 '절 이름'" 참조가 따라올 수 있게).

## 주의할 점
- 역링크 자동 확인 수단이 없으므로, 지운 경로를 링크하는 페이지가 남을 수 있다는 전제로 보고서에 표를 남긴다.
