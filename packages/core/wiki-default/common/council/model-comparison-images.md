모델·도구 비교 자료(표·한 장 이미지·보고)를 만들 때 수치를 어디서 가져오고, 사용자에게 어떤 형태로 보여 주는지 정리한다. 카드형 스코어카드(장점·단점·추천 용도·근거 수치)는 사용자가 "너무 기술적이고 내 프로젝트 사정에만 맞춰졌다"며 다시 요청했다.

## 언제 쓰나
- 사용자가 모델·도구를 비교해 달라고 할 때(비교표·이미지·보고)
- 위원에게 위키 성향 페이지([models/](models/claude-sonnet) 등)를 근거로 비교 그림을 맡길 때

## 수치 원본: 위키 '출처 N개'는 관찰 건수가 아니다
- Gen Wiki `models/<모델>` 페이지 머리의 '출처 N개'는 그 페이지를 만든 기억(문서) 출처 수다. 관찰 건수로 옮기면 틀린다(예: sonnet 24건 ↔ 실제 1029, terra 2건 ↔ 실제 30, 그래서 '관찰 적음·잠정' 평점이 잘못 붙었다).
- 관찰 건수·완주율·평균 tool call의 원본은 의장 시스템 프롬프트의 '모델별 강점·약점' 표(관찰 N건, 평균 call)다. 위키에서는 성향 문구만 가져온다.
- 위원에게 맡길 때 의장이 표의 수치를 지시에 그대로 붙여 주고 "이 값만 쓰고 '출처 N'은 건수로 쓰지 말 것", "이 값 외 수치 금지"를 적는다. 위키에 없는 등급(하위/주력/최상위 등)을 지어 붙이지 말라고도 적는다.

## 사용자가 원하는 그림 형태
1. 속도·신뢰도·지능·가성비처럼 항목별 10점 수치 점수
2. 총점 내림차순으로 한 줄씩 놓은 가로 누적 막대그래프
3. 장단점·추천 용도를 합친 일상언어 한 줄(25~45자, 예: "글쓰기·문장 다듬기가 강점, 큰 설계엔 아쉬움")
4. 한도·사용량·완주·실패 이야기, 기술 용어(tool call, CRLF, JSON 등), 프로젝트 고유 용어는 뺀다

## 지시에 넣을 것
- 위 4가지를 처음부터 넣는다. 사용자 원문을 인용하면 문구 톤(일상언어)이 맞는다.
- Pillow 정적 PNG로 만든다(Windows에서는 `py`로 실행, [Windows Python 버전 고르기](common/windows/windows-python-setup)). 한국어 폰트 로딩은 선례 스크립트를 본뜨게 한다.
- 완료 조건: "결과를 .council/shots에 복사 → Read로 열어 깨짐·겹침·잘림 확인 → 문제면 재렌더".
- claude sonnet medium이 6 tool call 안팎에 끝냈다([claude sonnet](models/claude-sonnet)).

## 주의할 점
- 항목을 똑같이 더하면 싸고 빠른 모델이 1위가 된다. 가중치를 쓸지, 쓰지 않았는지를 결과와 함께 사용자에게 알린다.
