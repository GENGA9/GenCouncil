마스터(비싼 모델)-서브에이전트 구조에서 서브가 한 일(대화·도구 기록·전체 diff)을 마스터에게 통째로 넘기면, 서브가 이미 읽은 토큰을 마스터가 다시 읽어 비용이 두 배가 된다. 대화 기록을 넘기지 않아도 '머지 전 전체 diff 검토'가 같은 낭비를 만들고, 가장 비싼 모델이 가장 큰 덩어리를 읽게 된다.
그래서 마스터는 고정 길이 요약과 diffstat으로 먼저 판단하고, 필요한 파일만 골라 읽으며, 큰 결과는 싼 모델에게 판정만 받는다.

## 언제 쓰나
- 의장이 위원 결과를 검토하고 머지할지 정할 때
- 멀티에이전트 도구(이벤트 문구·diff 열람 도구·프롬프트)를 설계하거나 고칠 때

## 방법
1. 서브 → 마스터에는 고정 길이 요약만 보낸다: 결과 요약(수백 자), 미완료, 실패 원인, diffstat(파일별 변경 줄 수, 15줄 상한 + 합계 줄).
2. 마스터는 요약·diffstat으로 먼저 판단한다. 문서·작은 변경은 바로 통합한다.
3. diff 열람 도구는 파일 필터(`git diff A...B -- <paths>`)와 작은 기본 한도(예: 20k자)를 두고, 잘리면 "파일을 골라 다시 읽어라"를 붙인다.
4. 크고 미덥지 않은 코드 결과는 마스터가 직접 읽지 않고 싼 검토 에이전트(sonnet급)에게 맡겨 판정만 받는다.
5. 저장소 탐색도 싼 모델(haiku급)이 읽고 경로·요약만 돌려주게 한다.

## 주의할 점
- 이벤트 문구 생성 함수에 diffstat 블록을 넣고, "diff:true로 검토" 같은 옛 취지 문장을 프롬프트·도구 설명·이벤트 문구 **전부**에서 바꾼다. 한 곳만 바꾸면 다른 곳 안내가 옛 습관을 유지시킨다.
- GenCouncil 구현 위치(예): `packages/council/src/session.ts` memberEventText(), `council.ts` memberInfo(files, maxChars), `git.ts` diffFull(paths).
- 이 작업을 위원에게 맡길 때의 지시 문구는 [claude sonnet](models/claude-sonnet)의 '코드 수정'.
