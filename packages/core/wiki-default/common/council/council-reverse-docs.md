메모·README·옛 문서에는 이미 바뀐 규칙이 남아 있어 그대로 옮기면 틀린다. 커밋이 1,000개를 넘으면 한 위원에게 무겁다.
사실 기준을 현재 코드로 못 박고, 역기획서는 장 묶음별로, 일지는 커밋 수 기준 날짜 범위로 나눠 병렬로 쓴다(4작업 병렬로 약 20분).

## 언제 쓰나
- 이미 진행된 저장소에서 "역기획서 + 날짜별 개발일지"를 요청받았을 때

## 방법
### 역기획서
- 장 묶음별 파일로 2명(뼈대 / 시스템)에게 나누고, 색인 README는 한 명만 쓴다.
- 지시: "사실 기준은 현재 코드, 기록과 다르면 '(기록과 다름)', 확인 못 하면 '(미확인)', 장 끝에 근거 파일 경로".
- 핵심 표는 "node 스크립트로 코드 상수와 대조"를 완료 조건에 넣는다.

### 개발일지
- 커밋 수 기준으로 날짜 범위를 나눈다. 형식 고정: 한눈에 표 + 날짜별 추가/변경/수정/배포.
- 완료 조건: "커밋 수가 git log 날짜별 집계와 일치". 의장은 `git log --format=%ad --date=short | sort | uniq -c`로 대조한다.

### 공통 확인
- "docs/<폴더> 밖 변경 없음"을 git status로 확인한다.

## 주의할 점
- 하위 모델이 쓴 일지는 해시가 맞아도 서술이 틀릴 수 있다 → 검증 위원이 커밋 메시지와 대조한다.
