단계와 금지가 명시된 좁은 일(버전 올림·배포·삭제 커밋·git 설정·측정·md 정리·push·재시작·큐 정리·시스템 점검·파일·행을 지정한 한 줄 수정·정해진 내용으로 파일 교체)을 적은 호출 수로 정확하게 한다.
진단·원인 분석·품질 평가는 하지 않으니 [claude sonnet](models/claude-sonnet)이나 의장에게 맡긴다.

## 잘하는 일
- low·medium으로 4~12 tool call에 정확히 끝내는 일: 버전 올림·wrangler 배포·라이브 바이트 대조, 지정 파일 삭제(`git ls-files` 확인 후 하나씩 `git rm`), 범위를 못 박은 `git config`(확인 출력까지), i18n 키 동기화, "merge → 원본 바이트로 되돌리고 2줄만 Edit 재적용", 여러 문서의 값 교체, 미추적 파일 해시 비교 후 삭제
- 정해진 내용으로 텍스트 파일 교체(low): "정확히 이 내용으로 두 텍스트 파일 교체"를 7회 호출로 끝냈다. 내용을 지시에 그대로 적어 줄 때만 맡긴다
- 파일·행·예시 문구를 준 한 줄 프롬프트(TS) 수정(low): 6 tool call로 끝내고 지시 범위 밖은 건드리지 않는다. 테스트 전에 dist 빌드가 필요하다는 것을 스스로 찾아 보고했다
- 공유 .git 유지보수(gc): 금지 목록(--prune=now·reflog expire·worktree prune 금지 등)을 지키고, 전후 count-objects·잠금·경고까지 보고한다. 바꿀 게 없으면 커밋하지 않고 이유를 적는다
- ffmpeg 단순 변환(무음 mp4+wav 분리, low): 명령 원형, ffprobe 수치 완료 조건(스트림 수·프레임 수·길이 오차·volumedetect), 덮어쓰기 금지를 주면 5번 호출에 끝내고 스스로 `-n`을 붙였다
- 폴더+.gitkeep 커밋 같은 아주 작은 일(low, advisor 없음): 3번 호출. 패킷 기본 규칙 `git add -A`와 지시의 금지가 부딪히면 좁은 쪽(지시)을 따르고 충돌을 RESULT.md에 적는다
- 파일 교체·manifest 채택 표시·누락 mp4 `git add -f` 커밋 같은 기록 일을 md5·JSON 파싱으로 확인하며 정확히 끝낸다. 원본 경로가 없으면 임의로 대체하지 않고 이유·한계를 적고, 규칙 충돌(큰 바이너리 커밋)은 의장 확인을 요청한다
- 머지한 기능 되돌리기(low): `git rm <새 파일들>` + `git checkout main -- <수정 파일들>` + 커밋 + `git diff main HEAD` 빈 결과 확인을 단계로 주면 3회 호출로 정확하다. 지시 밖 파일은 건드리지 않고, checkout 금지 규칙과의 충돌은 가정으로 적는다
- 측정: "소스 수정 금지, 측정만"으로 기준별 판정 표를 낸다(0%는 판 수를 늘려 다시 확인). 망친 md를 원본과 바이트 대조하고 CRLF를 유지하며 정리한다. 없는 섹션은 만들지 않고 보고한다
- push·재시작: 조상·diffstat·비밀 파일 확인, 경로 지정 스테이징, 양방향 커밋·해시 대조를 5~12 calls에 한다. fast-forward 확인 후 push+JS 청크 배포 확인, 유휴 확인 후 백엔드 재시작(PID·/health), 토큰으로 CLI 로그인 후 gated 접근 확인, config 기본값 변경+테스트 추가도 7~16 호출로 정확하다
- 메인 폴더 빌드→테스트→git status 기록→세션과 떨어진 재시작 예약도 PowerShell 명령을 그대로 주면 3~9 호출. "실패하면 재시작 안 함"을 지키고 ReturnValue·PID까지 보고한다. 토큰·비밀 "출력 금지"를 지킨다
- ComfyUI 큐 정리(내 id만 interrupt): 단계·금지가 명시되면 client_id·prefix까지 확인하고 정확히 처리한다
- 읽기 전용 시스템 점검(RAM 모듈, VRAM, ComfyUI `/system_stats`)을 몇 번의 호출로 정확히 끝낸다(low)
- 문구 초안의 규칙이 코드와 다르면 코드대로 고친다. 지시한 방식이 안 되면 우회하고 한계를 보고한다
- sonnet이 하던 운영 작업도 haiku로 충분하다

## 약한 일
- 줄 끝(CRLF/LF) 변경이 섞일 때가 있다
- 이전 값 비교·원인 분석은 하지 않는다. 재시작이 효과 없던 원인(로그 파일 잠금)을 못 찾았다
- Start-Process 종료 코드 1을 실패로 보고 다시 실행한다
- "비로그인 401 = 새 배포됨"처럼 지나치게 해석한다
- 판정 조건을 글자 그대로 따라서, 조건이 잘못 세워져 있으면("프록시 경로가 404가 아니면 재시작") 원인을 따지지 않고 폴링한 뒤 건너뛴다
- 서버 재시작으로 끊겨 인계받은 haiku는 상태 확인부터 하지만 중복 재시작 위험이 있다
- 지시 밖 집계값(크레딧 합계 등)은 건드리지 않는다

## 지시에 넣을 문구
- 단계와 금지: "이 두 명령만, 다른 설정 금지", "어느 줄부터 지울지 기준 문장", "어느 파일과 같게", "건드리지 말 부분", "강제로 끊지 말 것". 순서 번호·금지 목록을 쓰면 6~7 calls로 싸고 정확하다
- 파일 교체: 넣을 내용 전체를 지시에 그대로 적는다("정확히 이 내용으로")
- 코드 수정: "현재 구조: 파일:행 + 함수명" 목록과 예시 문구를 먼저 주고, 완료 조건에 정확한 명령(예: `npx tsc -b`, `node test/*.mjs`)을 적는다
- 숫자 완료 조건: 예) 특정 줄 정확히 6개, exit 0, fsck 정상, 전후 수치
- 커밋 범위: "git add -A / git add . 금지, 해당 파일만 add". 저장소 밖 결과물이면 "커밋 없음"
- 되돌리기: 파일 경로 전부, 검증 명령, 기대 결과(빈 diff)
- 재시작: "딱 1회, 종료 코드 무시, PID 변경과 /health 폴링으로 판단, 두 번 실행 금지". 재시작 명령(타임스탬프 로그명)과 배포 확인법(JS 청크 문구 검색)을 그대로 준다. 판정 기준을 정확한 순서로(프런트 새 페이지 200 → 재시작 → 프록시 경로 확인). 모호한 분기의 기본 행동은 "멈추고 보고"
- ComfyUI 큐: "내 client_id·prefix 작업만 interrupt/삭제, 남의 작업 금지"
- 명령 예시·성공 판정·금지 사항을 번호로 쓴다
- 필요한 집계값 갱신은 따로 명시한다. 다른 위원 worktree는 이미 정리됐을 수 있으니 복사 원본은 통합 브랜치 경로로 준다
- 배정: 비가역 단계(prune=now)는 sonnet, 단순 실행은 haiku. 품질 평가·실패 원인 분석은 의장이나 sonnet. 인계받은 haiku는 의장이 확인한 뒤 멈춘다
