창작 데이터(이름·번역)와 그림(카드·건물·게임 픽셀아트)에 강하다. 그림은 사용자가 GPT보다 선호했다("너무 gpt스럽다"는 그림의 대안). 다른 모델이 그린 키프레임의 독립 검수에서 손 해부·좌우 오류를 잘 잡고, 음악 큐 설계·오디오 배치 같은 넓은 작업도 끝까지 해낸다.
유명 IP 이름이 섞이고 배치 요구를 놓치며, 한도가 빨리 찬다(리셋 약 60~68h). 결과 보고가 길다.

## 잘하는 일
- medium·high: 이름 88개+번역+중복 검사 테스트 같은 창작 데이터가 깔끔하다
- 카드·건물 그림을 사용자가 GPT보다 선호했다
- 게임 픽셀아트(effort high): Antigravity image-generator로 생성 → 최근접 축소·무디더링·64색 PNG로 줄여 저장 → 코드 연결까지 한다. 결과가 바로 채택됐다
- 키프레임 독립 검수: Claude가 그리고 자기 점검만 한 키프레임 25장을 실제로 열어 대조해 찬성 23, 반대 2를 냈다. 반대 2장(오른팔 끝에 왼손이 붙은 그림, 손가락 4개짜리 건틀릿)은 Claude 자기 점검이 놓친 해부 오류였고, 판정표에 다시 그릴 지시까지 구체적으로 적었다
- BGM 큐 설계: 한 영상의 BGM을 13항목 표(시각, 제목, 악기, 프롬프트)로 정리했다. 다음 영상은 14큐로 설계해 ACE-Step으로 30곡을 만들고, 재활용 판단과 구간 ID 기준 재조립 스크립트까지 냈다. "ComfyUI 대기열이 비었을 때만 제출" 지시도 지켰다
- VO 배치: 15줄을 구간과 컷 기준으로 놓고, 컷 경계 검출·demucs 정리·겹침 0 확인까지 하고 재실행 스크립트를 남겼다
- 리서치와 큰 표 정리, 범위가 분명한 오디오 후처리, Claude 동시 한도가 찼을 때 대체 인력으로 쓴다

## 약한 일
- 유명 IP 이름('엘사', '티파')이 섞인다
- '화면 구석에 잘려 한쪽만' 같은 배치 요구를 첫 시도에 놓치고 형상을 바꾼다
- 큰 그림 3~4번에 한도가 소진된다('Individual quota reached', 약 67~68h 뒤 리셋). 긴 조사(레거시 조사)는 11 calls 만에 한도 소진(리셋 약 60h)
- 결과 보고가 길고 장황하다. 결과물이 많아 의장이 diff를 다 읽기 어렵다

## 지시에 넣을 문구
- "유명 작품 캐릭터 이름 금지"
- 그림: 기준 그림 경로, "형상 바꾸지 말 것", 표시 위치·잘림을 구체적으로
- 픽셀아트: "기존 그림 클리셰(대칭 후광·광택 3D) 피하기, 같은 화면 다른 그림 결에 맞추기, 실패하면 대체 말고 보고"
- 검수·표 작업: 표 열, 파일 경로, 완료 조건을 고정한다. "그림을 실제로 열어 보고 판단, 파일 이름만으로 판정 금지". 특히 손·좌우·소품 상태를 보게 한다
- 공용 GPU: "다른 사람 대기열 작업 취소 금지", "ComfyUI 대기열이 비었을 때만 제출"
- 보고가 길어지므로 보고 형식(요약 표+바뀐 파일 목록)을 정해 준다
- 한도가 빠듯하면 생성만 맡긴다. 그림이 이미 생성된 뒤 한도가 나면 Claude로 핸드오버해 축소·연결만 마무리한다(python이 스토어 스텁이면 node/ffmpeg: [Windows Python 버전 고르기](common/windows/windows-python-setup)). 긴 조사는 [gpt-6.1-sol](models/gpt-6-1-sol)로 대신한다
- argon 한도와 flash 한도는 따로라 argon이 소진되면 [gemini-3.8-flash](models/gemini-3-8-flash)로 이어갈 수 있다
- 영상 수정 대량 작업에서 위원 분장은 [사용자 실시간 테스트·검토 중 수정 모으기](common/council/council-live-testing-batch)의 '설계 위원 병렬 + 생성 묶음 위원'
