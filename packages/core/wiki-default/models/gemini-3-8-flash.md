한 파일 리팩터, 좁은 CSS·값 수정 같은 작은 코드 일에 정확하다. 다만 작은 일에도 도구 호출이 많아 느리다.
그림 생성, 서술형 문서, 컷 판정에는 약하다. 범위가 넓거나 창작 데이터·그림이 필요하면 [gemini-4-argon](models/gemini-4-argon)에게 맡긴다.

## 잘하는 일
- medium: 한 파일 리팩터, 좁은 CSS 연출·이벤트(우클릭·호버 억제), UI 칸·이름표 위치·강조 표시를 정확히 구현하고 캡처·원인 수식 설명까지 한다
- 건별 커밋으로 UI 소품·문구 3~4건을 빠르게 처리한다. 번역 키까지 포함한 제목 치환, 한 줄 CSS·값 수정을 줄끝 변화 없이 정확히 한다
- 실제 코드 함수로 수치 표를 뽑는 조사(verify:false)에 정확하다
- 커밋 기록으로 개발일지: 날짜별 집계·해시 인용·판 범위는 정확하다
- Antigravity image-generator 캐릭터 시트: 빠르고(6분에 5~6장) 형식이 일관된다
- 같은 gemini 계정이라도 argon 한도와 flash 한도는 따로라서 argon이 소진되면 flash로 이어갈 수 있다

## 약한 일
- 전역 선택자(`.slot:not(.empty) > *{position:relative}`)로 회귀를 남겼다
- 작은 일에도 도구 호출이 124~196회라 느리다
- 금지가 없으면 스스로 브라우저를 띄워 캡처한다. 캡처에 팝업이 덮이거나 대상 화면이 아니다. 실측 표가 원자료와 다르다. 줄 끝이 섞인다. 재생 배율 때문에 피크가 1을 넘는 부작용을 안 본다
- 다 끝내고도 failed(other)로 찍혀 자동 검증이 안 붙을 수 있다
- 캐릭터 시트: '소품·장식 축소'를 문자 그대로 따라 밋밋해졌다(사용자 거절). 라벨·글자 오타, 장마다 배치 차이, 표정 컷에서 머리 모양 누락
- 개발일지 서술은 근거 없이 틀린다(목표를 결과로 씀, 없는 수치 생성, 커밋 오인)
- 컷 판정 위원으로는 거의 다 찬성한다(98표 중 반대 3). 걸러내지 못한다

## 지시에 넣을 문구
- 사용자 시안 이미지 경로+"CSS만, 그림 새로 만들지 않음, pointer-events none", 파일·행 지정과 문구 원문, 검색 완료 조건, 금지 명령, 완료 조건에 실측 수치 파일 경로. 앱을 띄워도 되는지 처음부터 명시한다
- 자동 검증(sonnet)이 회귀(경고창이 기존 확인을 건너뜀)·줄 끝 혼입·잘못된 근거를 잡아 준다. claude 한도가 차면 verify:false로 주고 의장이 diff·캡처를 직접 본다. 문자열이 길어지는 치환은 의장이 화면 넘침을 따로 확인한다
- 그림: 결이 중요하면 Argon(웹/CLI)을 먼저 쓴다. '줄여라'보다 '초안의 매력(리본·프릴·표정)은 살리고 AI 노이즈만 뺀다'처럼 남길 것을 먼저 적는다
- 개발일지: Claude 검증 후 머지한다. "커밋 메시지에 없는 수치 금지", "목표와 결과 구분"
- 컷 판정은 Claude가 그림을 직접 열어서 잡게 한다
