# GenCouncil 설계 제안

> 여러 AI(클로드 · 제미나이 · GPT, 다중 계정)를 "제작위원회"로 묶어
> 의장(Chair)이 업무를 분장·취합하고, 내 PC 전체의 공유 기억(Space)을
> 축적하며, 모바일에서도 작업을 이어갈 수 있는 로컬 오케스트레이션 앱.

작성일: 2026-10-22 · 상태: v0.5 (1~5단계 구현 완료; Tauri 빌드만 미검증)

> 5단계 구현 메모: 상주는 Windows 로그온 예약 작업(`schtasks ONLOGON` + 숨김 VBS 런처)으로, 데스크탑은 Edge/Chrome 앱 모드 창(`gencouncil desktop`)으로 먼저 해결했고 Tauri 트레이 앱은 스캐폴드만 두었다(Rust 없음). 알림은 Telegram 봇 양방향(알림 + 의장에게 전달). 회고는 안건 종료 전 의장 턴으로 공유 기억·persona·제안 검토를 자동화한다.

> 4단계 구현 메모: 한도 감지는 CLI 출력의 오류 문구를 분류하는 방식(`quota.ts`)이고, 사전 잔량 조회는 CLI가 제공하지 않아 하지 않는다. 그래서 위원은 단계마다 STATE.md를 쓰고, 인계는 같은 worktree·브랜치에서 새 프로세스를 띄우는 것으로 구현했다(§7의 "role.md + state.md" 원리를 위원에게는 TASK.md + STATE.md + HANDOVER.md로 적용). 모델 분담은 클로드 코드 advisor 패턴(Sonnet 실행 · Haiku 탐색 · Opus 판단)을 의장과 위원 기본값으로 채택했다.

> 구현 중 바뀐 결정: 의장과 클로드 위원은 Claude Agent SDK가 아니라 **클로드 코드 CLI 헤드리스(`claude -p --resume`)**로 구동한다. SDK는 API 키 과금이라 "구독 계정·다중 계정·한도 핸드오버"라는 목적과 맞지 않기 때문이다. 제미나이도 같은 방식(`gemini -p`)이라 드라이버가 통일된다. 의장 전용 도구는 council 프로세스가 **HTTP MCP**로 내주고, 의장은 `--mcp-config`로 붙는다. 이 HTTP 서버가 3단계 웹 UI의 백엔드가 된다.

---

## 0. 한 줄 요약

**"내 PC에 상주하는 서버 1개 + 그 위의 웹 UI 1개"** 구조를 추천한다.

- 서버(Council Server)가 의장·위원 에이전트를 띄우고, git worktree로 작업을 격리하고, 공유 기억을 관리한다.
- UI는 웹 앱 하나를 만들어 **데스크탑에서는 Tauri 창으로, 외부에서는 Tailscale 주소의 PWA로** 똑같이 쓴다. UI를 두 번 만들지 않는다.
- 위원들은 **MCP 서버 하나**를 통해 공유 기억·작업판·핸드오버에 접근한다. 클로드 코드, 제미나이 CLI, 코덱스 CLI 모두 MCP를 지원하므로 제공자마다 따로 붙일 필요가 없다.

## 1. 문제 → 설계 원칙

| # | 문제 | 설계 원칙 |
|---|------|-----------|
| 1 | 세션마다 해결책을 다시 찾는다 | **Space 공유 기억**을 파일(markdown)로 두고, 모든 위원의 시스템 프롬프트에 색인을 주입 + MCP 검색 도구 제공. 안건 종료 시 의장이 "회고"로 교훈을 추출해 기록 |
| 2 | 여러 AI가 같은 폴더를 번갈아 수정해 커밋이 꼬인다 | **위원 1명 = worktree 1개 = 브랜치 1개.** 위원은 main을 절대 만지지 않고, 통합(머지)은 의장만 한다 |
| 3 | 병렬 작업 지시가 어렵다 | 내가 위원에게 직접 지시하지 않는다. **의장에게 목표만 말하면** 의장이 작업으로 쪼개고, 위원을 배정하고, 결과를 취합한다 |
| 4 | 외부에서 연속성이 없다 | 상태가 전부 **서버(내 PC)의 파일/DB에 있고** UI는 얇은 클라이언트. 폰에서 접속해도 같은 대화·같은 작업판 |
| 5 | 한도 소진 시 작업이 끊긴다 | 위원·의장 모두 **체크포인트마다 state.md 갱신**. 한도 오류 감지 시 state.md를 들고 다른 계정/모델로 **핸드오버** |

## 3. 개념 모델

```
Space (내 PC 전체, 1개)
 ├─ memory/            공유 기억 (문제해결법, 도구 위치, 규약)
 ├─ accounts.yaml      제공자 × 계정 × 인증 프로필 × 한도 상태
 ├─ guidelines/        AI 성향별 업무 분장 템플릿 (프로젝트에서 복사·수정)
 └─ projects/
     └─ Project "MY GAME 제작위원회"
         ├─ repo: D:\work\my-game         (실제 코드/리소스 저장소)
         ├─ guidelines.md               이 프로젝트의 분장 규칙 (수정 가능)
         ├─ chair: {model, effort}      의장 설정 (도중 변경 가능)
         └─ agendas/
             └─ Agenda "밸런스 안건"
                 ├─ goals[]             목표1, 목표2, 목표3
                 ├─ tasks[]             의장이 쪼갠 작업 (상태, 담당 위원, 브랜치)
                 ├─ members[]           이 안건에 투입된 위원
                 ├─ integration branch  agenda/balance
                 └─ transcript          나 ↔ 의장 대화
```

### 역할은 "세션"이 아니라 "파일"이다

의장과 위원은 특정 모델 세션에 묶이지 않는다. 역할의 정체성은 다음 세 파일에 있다.

- `role.md` : 역할 정의(의장/위원), 담당 범위, 금지사항
- `state.md` : 지금까지 한 일, 하다 만 일, 다음 할 일, 막힌 점 (체크포인트마다 갱신)
- `context/` : 참고해야 할 파일 목록, 관련 공유 기억 링크

따라서 **의장 교체 = 다른 모델 세션을 띄우고 같은 세 파일을 읽게 하는 것**뿐이다. 핸드오버도 같은 원리로 동작한다.

## 4. 위원 연결 방식 (자동 vs 수동 릴레이)

솔직한 제약: 웹 제미나이, AI Studio, Antigravity는 **헤드리스 API가 없다.** 브라우저 자동화로 억지로 붙이면 깨지기 쉽다. 그래서 위원을 두 종류로 나눈다.

| 종류 | 대상 | 연결 방법 | 다중 계정 |
|------|------|-----------|-----------|
| **자동 위원** | 클로드 코드 | Claude Agent SDK (TS) | `CLAUDE_CONFIG_DIR`를 계정별로 분리 |
| | 제미나이 CLI | `gemini` 프로세스 (headless `-p`) + MCP | 프로필 디렉토리를 계정별로 분리 |
| | 코덱스 CLI (GPT) | `codex` 프로세스 + MCP | 동일 |
| **릴레이 위원** | 웹 제미나이, AI Studio, Antigravity | 의장이 **작업 패킷**(프롬프트 + 첨부할 파일 묶음 + 결과 양식)을 생성 → 내가 복사해 붙여넣기 → 결과를 UI 드롭존에 붙여넣기/파일 드롭 → 서버가 해당 위원 worktree에 적용 | 사람이 전환 |

릴레이 위원은 "느리지만 공짜 한도"로 취급하고, 의장이 **대기 시간이 길어도 되는 작업**(리서치, 대안 설계, 대량 리뷰)을 주로 배정하게 가이드라인에 적는다. 결과 양식을 고정(예: `=== FILE: path ===` 블록)하면 서버가 자동으로 파일에 반영할 수 있다.

> Antigravity가 로컬 폴더를 직접 편집하는 경우: 그 폴더를 **릴레이 위원 전용 worktree**로 열어 주면 된다. main을 건드리지 않으니 충돌이 생기지 않는다.

## 5. 충돌 해결: worktree-per-member

```
main ◀── 의장만 머지
 └─ agenda/balance            (안건 통합 브랜치, 의장 소유)
     ├─ balance/claude-1      (worktree: .worktrees/claude-1)
     ├─ balance/gemini-1      (worktree: .worktrees/gemini-1)
     └─ balance/relay-agy-1   (worktree: .worktrees/relay-agy-1, Antigravity가 여기서 작업)
```

규칙

1. 위원은 자기 worktree 안에서만 작업하고 자기 브랜치에만 커밋한다.
2. 작업 완료 시 위원은 `task.done`을 호출한다. 의장이 diff를 검토하고 안건 브랜치에 머지한다.
3. 충돌이 나면 **의장이 해결**한다. 못 풀면 내게 UI로 묻는다(두 diff 나란히 보여주기).
4. 안건이 끝나면 안건 브랜치를 main에 머지하고 worktree를 정리한다.
5. 리소스(바이너리) 파일은 가이드라인에서 **한 위원에게만 배정**하도록 의장에게 지시한다. 바이너리는 머지가 안 되기 때문이다.

## 6. Space 공유 기억

```
~/.gencouncil/space/memory/
 ├─ INDEX.md                 한 줄 요약 색인 (모든 위원 프롬프트에 주입, ~2k 토큰 상한)
 ├─ solutions/               "X 문제는 Y로 해결" (frontmatter: tags, project, date, verified)
 ├─ tools/                   도구 위치·실행법 (ffmpeg 경로, 빌드 명령 …)
 ├─ conventions/             규약 (커밋 메시지, 폴더 구조, 네이밍)
 ├─ accounts/                계정별 특성·한도 패턴 (예: 제미나이 B계정은 오후에 리셋)
 └─ personas/                각 AI의 성향 관찰 기록 (분장 가이드라인의 근거)
```

- 저장소는 **git으로 버전 관리**한다. 사람이 읽을 수 있고, 잘못 쓴 기억은 diff로 되돌린다.
- MCP 도구: `memory.search(query)` (SQLite FTS5), `memory.read(id)`, `memory.propose(entry)`.
- 위원이 직접 쓰지 않고 **제안**만 한다. 의장이 안건 종료 시 "회고" 단계에서 제안을 검토해 승인/병합한다. 쓰레기 기억이 쌓이는 것을 막는다.
- 프로젝트 전용 기억은 `projects/<name>/memory/`에 두고, Space 기억과 함께 검색된다.

## 7. 핸드오버 프로토콜

```
정상 루프:   [작업] → N턴마다 state.md 갱신 → [작업] …
한도 감지:   SDK/CLI 429·quota 오류 or 계정 레지스트리 잔량 < 임계치
             → 즉시 state.md 최종 갱신 (가능하면)
             → accounts.yaml에 "소진, 예상 리셋 시각" 기록
             → 같은 역할의 새 위원을 다른 계정/모델로 생성
             → role.md + state.md + context/ 를 읽고 이어감
             → 의장이 "핸드오버 확인" 메시지로 연속성 검증
```

- 감지가 실패해도 괜찮도록 **"N턴마다 체크포인트"가 기본**이다. 감지는 보너스다.
- 의장도 같은 프로토콜로 교체된다. 의장 교체 UI(모델·추론 수준 드롭다운)는 내부적으로 핸드오버를 호출한다.
- 핸드오버 패킷에는 "지금 열려 있는 worktree 경로, 마지막 커밋, 실패 중인 테스트"를 반드시 넣는다.

## 8. 모바일 연속성

- **Tailscale**로 PC와 폰을 사설망에 묶고, 서버의 주소(`http://pc.tailnet:7700`)를 폰에서 PWA로 설치한다. 포트 포워딩·공인 IP가 필요 없다.
- UI는 하나다. 폰에서는 좌/중/우 3단이 탭 3개로 접힌다.
- 푸시 알림 대신 가벼운 방법: Telegram 봇을 선택 플러그인으로 둔다. "의장이 묻고 있음", "안건 완료" 같은 이벤트를 보내고, 봇에 답하면 의장 대화에 들어간다.
- 서버는 Windows 서비스(또는 시작 프로그램)로 상주시킨다.

## 9. UI 매핑 (레퍼런스 → 화면)

```
┌─ 좌: Space 트리 ─┐ ┌─ 중: 의장 ─────────────────┐ ┌─ 우: 위원 카드 ─────┐
│ SPACE             │ │ 의장 - 클로드 opus5.5 높음   │ │ 제미나이1   [활동그래프] │
│  MY GAME 위원회 │ │  ▸ 모델/추론 드롭다운 = 교체   │ │  상태·브랜치·한도 바   │
│   밸런스 안건  ●  │ │ ┌ 목표 ───────────────────┐ │ │ 클로드1    [활동그래프] │
│   데스크탑앱 제작  │ │ │ 목표1  ━━━━━━░░ 3/5 작업 │ │ │ 지피티1    [활동그래프] │
│  H3_Project 위원회│ │ │ 목표2  ░░░░░░░░ 대기    │ │ │ ─────── 대기 중 ─────  │
│                   │ │ │ 목표3  ✔ 완료            │ │ │ 클로드2        ▽ 접힘  │
│ ───────────────── │ │ └─────────────────────────┘ │ │ 제미나이(agy)1 ▽ 접힘  │
│ 현재 안건 고정     │ │  나 ↔ 의장 채팅              │ │  (릴레이: 패킷 대기)    │
│  ▦ 밸런스안건      │ │  (의장이 작업 분장·취합 보고) │ │                       │
└───────────────────┘ └─────────────────────────────┘ └───────────────────────┘
```

- **좌 하단 고정 안건**: 지금 보고 있는 안건. 폰에서는 이게 첫 화면이다.
- **목표 박스**: 목표를 펼치면 의장이 쪼갠 작업 목록과 담당 위원이 보인다. 목표 추가는 여기서 직접 입력하거나 채팅으로 의장에게 말한다.
- **위원 카드의 그래프**: 최근 활동(토큰/분, 도구 호출)과 한도 잔량. 클릭하면 그 위원의 로그·diff·state.md.
- **접힌 카드**: 대기/소진/릴레이 대기 위원. 릴레이 위원은 "패킷 복사" 버튼과 "결과 붙여넣기" 드롭존이 펼쳐진다.
- **가이드라인 편집**: 프로젝트 이름 옆 설정 아이콘 → `guidelines.md` 편집기.

## 10. 기술 스택 제안

| 층 | 선택 | 이유 |
|----|------|------|
| 서버 | Node 22 + TypeScript, Hono(HTTP) + ws(WebSocket) | Claude Agent SDK와 MCP SDK가 TS 우선. CLI 프로세스 제어가 쉽다 |
| 메타데이터 | SQLite (better-sqlite3) + FTS5 | 단일 파일, 백업 쉬움, 기억 검색 |
| 기억·상태 | markdown 파일 + git | 사람이 읽고 고칠 수 있어야 한다 |
| 위원 드라이버 | `@anthropic-ai/claude-agent-sdk`, `gemini` CLI, `codex` CLI, relay | 각 드라이버는 같은 인터페이스(`start / send / onEvent / checkpoint / stop`)를 구현 |
| 위원 ↔ 서버 | GenCouncil MCP 서버 (`@modelcontextprotocol/sdk`, stdio 또는 HTTP) | 제공자 무관 공통 통로 |
| UI | React + Vite, PWA | 데스크탑·모바일 동일 코드 |
| 데스크탑 | Tauri 2 (서버를 사이드카로 실행) | Electron보다 가볍고, 트레이 상주에 적합 |
| 원격 접속 | Tailscale | 설정 없는 사설망 |

대안을 고려하고 배제한 것

- 클로드 코드 서브에이전트만 사용: 제미나이·GPT·다중 계정을 못 쓴다.
- 브라우저 자동화로 웹 제미나이 구동: 깨지기 쉽고 약관 위험. 릴레이 방식으로 대체.
- Electron: 상주 앱치고 무겁다. UI가 웹이므로 Tauri로 충분.

## 12. 단계별 로드맵

각 단계는 그 자체로 쓸 수 있는 결과물을 낸다. 1단계만 있어도 문제 1번이 해결된다.

| 단계 | 산출물 | 해결되는 문제 |
|------|--------|---------------|
| **1. 기억 + MCP** | Space memory 폴더 구조, FTS 검색, MCP 서버. 지금 쓰는 클로드 코드·제미나이 CLI에 바로 연결 | 1 |
| **2. 의장 + worktree** | 의장 루프(목표→작업 분장→위원 생성→취합), 자동 위원 2종(클로드, 제미나이 CLI), worktree 통합. UI는 터미널/최소 웹 | 2, 3 |
| **3. 웹 UI + 모바일** | 레퍼런스 3단 UI, PWA, Tailscale 연결, 체크포인트 state.md | 4 |
| **4. 핸드오버 + 계정 레지스트리** | 한도 감지, 자동 교체, 의장 교체 UI, 릴레이 위원 패킷 흐름 | 5, (2의 웹 도구) |
| **5. 데스크탑 패키징** | Tauri 트레이 앱, 서비스 상주, 회고 자동화, Telegram 알림 | 완성도 |

1단계는 작다. 기존 워크플로를 바꾸지 않고 MCP 서버만 추가하는 것이라 당장 이득이 보인다.

## 13. 가정과 결정 필요 사항

가정한 것

- 프로젝트 저장소는 git을 쓴다(안 쓰는 프로젝트는 서버가 `git init`을 제안).
- 제미나이 자동 위원은 **제미나이 CLI**로 붙인다. 웹 제미나이·AI Studio·Antigravity는 릴레이.
- 언어는 TypeScript. 기존 chatterbox가 다른 스택이면 알려 달라.

결정이 필요한 것

1. 1단계부터 시작해도 되는지, 아니면 UI 골격(3단계)을 먼저 보고 싶은지.
2. 릴레이 위원 방식으로 웹 도구를 쓰는 데 동의하는지, 아니면 브라우저 자동화를 실험해 볼지.
3. 알림 채널: Telegram, 아니면 PWA 푸시만.
